# 离线真题维护手册

## 用户入口

直接双击：

```text
E:\N1_language\index.html
```

该文件内嵌题库数据、CSS 和应用代码；图片和音频通过相对路径读取项目中的本地文件。因此不能只复制 HTML 而不复制资源目录。

## 构建

在项目根目录运行：

```powershell
python .\offline-exam-tool\build_explanations.py
python .\offline-exam-tool\build_offline_exam.py
```

构建会更新：

- `offline-exam-tool\data.js`
- 根目录 `index.html`
- `offline-exam-tool\practice-data.js`：从正式标签映射生成的专项练习元数据。

页面源码现在位于 `offline-exam-tool/app.js`、`styles.css` 与 `index.template.html`；`special-practice.js` 负责题池筛选、无放回抽样和考点统计。烧饼目录下的早期页面源码作为原始版本保留，统一入口不再从那里读取应用代码与样式。

专项练习元数据独立于 `data.js`，因此重建网页不会使已审核的原题数据指纹失效。`build_practice_data.py` 按 ID 关联所有已标记题目，不硬编码期次或题数；新增标注更新知识库映射后重建即可生效。篇章语法题会关联本期共享全文。

## 校验

```powershell
python .\offline-exam-tool\verify_offline_exam.py
```

成功时应显示 `pass`，并更新：

```text
offline-exam-tool\offline_exam_verification.json
```

校验内容包括：

- 期次和五个科目是否存在；
- 题目 ID 是否唯一；
- 答案是否在选项范围内；
- 图片和音频路径是否存在；
- 2023.07–2025.12 增量期次题量是否符合预期；
- 2025 文字、词汇、语法和阅读是否误用占位选项。
- 2023–2025 的問題1读音词和問題3近义词是否完整保留下划线强调。
- 2025.12 向前十期是否每题都有通过最低质量门槛的解析及解析来源。

静态生成解析还需运行内容模板审计：

```powershell
python .\offline-exam-tool\audit_ai_explanations.py
```

报告写入 `offline-exam-tool\explanations\quality-audit.json`，按题目 ID 标记旧语法兜底句、缺少语法逐项字段、阅读通用模板、听力通用模板和占位选项。格式通过不代表内容事实正确，文字词汇等未命中模板的解析仍需人工抽查。

## 可选本地服务器

```powershell
python .\offline-exam-tool\start_offline_exam.py
```

随后访问 `http://localhost:8765/`。需要把答题记录写入项目时应使用此方式。

启动器使用单实例端口：已有题库服务时会直接复用并打开页面，同时保留提示窗口直到用户按 Enter；新服务绑定端口时采用 Windows 排他监听，避免多个 Python 进程同时占用 8765。旧端口刚关闭时会自动短暂重试。

## Gemini 逐题对话

- 顶部“AI 配置”页保存 Google AI Studio API Key；模型固定为 `gemini-3.6-flash`。
- Key 保存在 `offline-exam-tool\config\gemini.json`，服务端状态接口只返回是否已配置，不会把 Key 回显给页面。
- AI 对话只在项目启动器的 localhost 模式可用；直接双击根目录 `index.html` 时不可用。
- 从历史页点击“查看详情”后，每道题右侧都有一段互相独立的对话。页面向 Gemini 发送期次、科目、题号、题目 ID、大题说明、题干、选项、用户答案、正确答案、答题理由和排序。
- 阅读题会把 `passage` 或题库中合并存入 `question` 的文章以 `articleOrPassageFullText` 完整发送；同一文章的后续小题会回溯到最近的文章起始题，确保 AI 能结合全文解释。用户点击发送前，题目和历史记录仍只保存在本地。
- 对话内容当前只保留在本次页面会话中，不写入答题历史文件。
- 历史回放中的 AI 面板最大高度跟随本题“题目＋解析”区域；消息区域可独立滚动。桌面端可拖动面板右下角调整宽度和高度，窄屏时宽度限制在题卡范围内。

## 答题历史

- 通过 `start_offline_exam.py` 打开时，每次提交在 `offline-exam-tool\history\records` 中写入一个独立 JSON，浏览器 `localStorage` 同时作为缓存。
- 文件名格式为 `期次+科目+本地提交时间.json`，例如 `2024.12+文字・词汇+2026-08-29_15-47-11-376.json`。
- 直接双击 `index.html` 时受浏览器权限限制，只写入浏览器缓存。
- 存储键：`sbry-n1-offline-history-v1`。
- 每条记录包含期次、科目、提交日期时间、耗时、分数、逐题结果、整题理由和每个选项的独立理由。解析不再复制进新记录；历史回放始终按题目 ID 关联当前题库的最新解析。
- 文字与词汇在答题界面中合并为“文字・词汇”，底层数据仍保留两个分类以兼容原始来源。
- 期次下拉框会显示该期最后一次提交的正确率。
- 每张题卡顶部显示完整的唯一题目 ID，并提供复制按钮，方便按 ID 定位题目。
- 解析按结论、各选项、译文/语法/思路分行；生成解析和追加点评分别使用“AI 生成解析”“AI 点评”标签。AI 生成的文字读音题还会说明错误读音实际对应的词，或明确标注其不是常用规范词形，并在必要时总结浊音、长音、音训读等常见误区。
- AI 生成的词汇問題2会逐项给出词义、常见搭配和语境差别；問題3额外解释题干词义并比较近义词；問題4逐项说明用法正误，错误例句同时给出更自然的替换表达。
- AI 生成的语法解析会具体标出各选项所表达的逻辑关系，以及与题干要求冲突的接续、时态或语气；排序题直接显示完整编号顺序和对应片段，不在各选项后重复解释顺序。
- 题库静态解析由 Codex 在 `grammar_explanation_details.py` 等维护表中逐题编写和核对；Gemini API 只用于网页历史回放里的交互式对话，不用于批量生成或更新题库解析。
- 首页学习概览按历史记录显示总体正确率、提交次数、学习天数、累计用时、各科表现、最近趋势、薄弱题型和最近答题。
- 答题页左侧题目目录使用未选择、已选择、正确、错误四种状态，并支持点击题号跳转。
- 语法問題6使用四项排序控件，第 3 位固定为 ★；提交记录保存完整 `order`、`starPosition` 和由 ★ 位置得到的答案。
- 每题可单独“显示正确答案”：只判定该题并显示解析，不写历史、不停止整科答题；若之后整科提交，以 `answerRevealedBeforeSubmit` 标记提前查看答案的题目。
- 历史页支持按期次和科目组合筛选；“查看详情”会进入只读答题界面，恢复当次答案、排序、理由和对错，并统一显示当前题库的最新解析。旧记录内即使存在解析快照也会忽略。
- 清理浏览器数据前先从页面“答题历史”导出 JSON 备份。
- 双击模式与 localhost 模式记录不共享；首次切换时从双击页面导出，再在 localhost 页面导入，导入记录会同步写入项目。

## 修改后的最低验收

专项练习回归检查：

```powershell
node .\offline-exam-tool\tests\test_special_practice.js
python -m unittest discover -s .\offline-exam-tool\tests -p "test_*.py"
python .\tools\build_language_taxonomy.py --check
python .\tools\build_grammar_taxonomy.py --check
```

专项记录使用 `mode: special`，保存筛选条件、指定题数、随机生成的题目 ID 顺序与逐题原期次/科目。存储仍走同一历史接口，回放按原 ID 关联当前解析。首页考点统计按作答次数汇总普通和专项记录；重复作答重复计数，多标签题分别计入对应标签，未提交草稿不计入统计。提前看答案单独显示次数。

浏览器验收还应覆盖：三级“全部”与联动筛选、空题池和非法题数、题池不足、混合科目排序题、共享文章、刷新保留随机顺序、提交与历史回放，以及普通答题继续正常工作。

1. 运行构建脚本。
2. 运行校验脚本并确认 `pass`。
3. 打开根目录 `index.html`。
4. 至少检查一个烧饼期次、一个 JLPT4YOU 期次和一个 2025 期次。
5. 检查文字题真实选项、阅读长文、听力音频、提交判分和历史记录入口。
6. 检查选项旁的理由框、提交后的解析及历史详情中的解析与选项理由。
7. 检查题目目录状态切换，以及语法問題6的加入、移动、移除、★判分和历史排序显示。
8. 检查单题显示答案不会新增历史，并且修改答案后会重新判定。
9. 检查历史组合筛选、只读回放及返回历史后保留筛选条件。
10. 通过项目启动器检查 AI 配置状态；打开一条历史记录，确认每题右侧都有独立对话框，并确认未配置 Key 时不会发出 Gemini 请求。
